# 진행도 기록 형식

> 2026-08-23. 로드맵 md의 체크박스는 건드리지 않는다.

```
data/
├── progress/<분야>-progress.json   북마크. 분야당 1파일. Claude가 읽는 것
└── log/<분야>/<로드맵 경로>.jsonl  전체 이력. 로드맵당 1파일. 붙이기만
```

- **progress는 손댄 로드맵만 담는다** (2026-08-27 개정). 전 로드맵 자리를 빈 틀로 미리 깔던 방식은
  매 세션 13KB를 읽어 한 줄을 얻는 낭비였다 — `software-progress.json` 13.1KB · 키 181개 · 실기록 1개.
  개정 후 9분야 합계 **165바이트**
- progress는 완료 지도도 커서도 아니라 **섹션별 요약 + 진행중 목록**
- %·스탯 계산의 원천은 log(재생 집계). progress는 캐시 —
  **`python tools/build_stats.py`가 로그에서 다시 만든다.** 손으로 고치지 말 것
- progress에 없는 로드맵 = 미진행. `lv`도 `doing`도 없는 `{}` 레코드는 집계에서 건너뜀

## progress

```json
"skill-based/Data-DB/redis": {
  "doing": [ { "sec": "4. Core Data Structures", "sub": "Sorted Sets", "item": "ZADD", "at": "2026-08-25" } ],
  "secs": { "1. What is Redis?": "5/1/6", "4. Core Data Structures": "2/0/9" }
}
```

- 키: 분야 폴더 기준 상대경로, 확장자 없음. `sec`: `## ` 없이 `N. 제목`.
  **`item`: 항목 *이름*만** — 항목 텍스트가 `English Name / 한국어 설명`이면 첫 ` / ` 앞부분
- **`sub`: 서브섹션(`###`) 제목. 섹션 직속 항목이면 생략**(= null)
- **`secs` 값은 `완료/이론완료/전체`** (lv:4 / lv:3 / 분모). 프론트 표기와 같은 3연.
  **손댄 섹션만 담는다** — 없는 섹션은 미진행이고 분모는 로드맵 json이 안다
- `doing` = 진행중 목록(`doing:true`인 항목). **로그가 있는 자기 항목만** — 진행중인 위임 칸은 여기 안 실린다
  (실제 할 일은 대상 로드맵에 있고, 그쪽 progress에 이미 실려 있다)
- **`secs`의 분모에는 위임 칸이 들어간다** (2026-08-27, `docs/stat-model.md` 규칙 8).
  그래서 **자기 항목을 하나도 안 건드린 섹션이 progress에 뜰 수 있다** — 위임한 대상 로드맵이
  진행됐다는 뜻이다(`cpp` §1의 `0/0/4`가 그 예: `c` 로드맵에 기록이 있어 위임 칸이 부분 진행).
  위임 칸의 **진행중(doing)은 대상에 `doing:true` 레코드가 있을 때만** — 부분 진행과 별개다(2026-08-29).
  **위임 칸엔 로그를 쓰지 않는다** — 쓸 곳은 대상 로드맵의 jsonl이다

### 커서를 없앤 이유 (2026-08-27)

옛 형식은 `"last"`에 **최근 완료 항목 하나**를 담고 "그 다음 항목"으로 이어가는 방식이었다.
**항목 하나가 위치를 대표하는 구조는 학습이 선형일 때만 성립한다** — PART 3을 하다 PART 1을
건드리면 `last`가 마지막 하나만 가리켜 앞엣것이 사라졌다. 커서를 여러 개로 늘려도 같은 병이다.
섹션별 요약은 순서를 안 타므로 아무 파트나 아무 순서로 해도 그대로 남는다.
로그(jsonl)는 원래부터 `(sec, sub, 이름)` 키라 순서와 무관했다 — 막고 있던 건 북마크 쪽이었다.

## 읽기 층위 — 입력 토큰 절약

| 언제 | 읽는 것 | 크기 |
|---|---|---|
| 세션 시작 · 뭐 하고 있었나 | `data/progress/<분야>-progress.json` | 분야당 1KB 미만 |
| 로드맵 하나를 이어서 할 때 | 그 로드맵 md의 해당 섹션 + 그 로드맵 jsonl | 섹션 단위 |
| 화면 전체 렌더 | 로드맵 json + jsonl (프론트가 함 — 대화 토큰 아님) | 상관없음 |

로드맵 하나당 평균 66항목(중앙값 71 · 최대 `cyber-security` 295)이라 jsonl은 다 채워도 한 파일 몇십 KB다.
**분야 전체를 훑지 말 것** — 필요한 로드맵 하나만 연다

## log

```
{"at":"2026-08-23","sec":"1. What is Redis?","item":"Cache","lv":2,"ev":"개념만 훑음"}
{"at":"2026-08-25","sec":"1. What is Redis?","item":"Cache","lv":3,"doing":true,"ev":"이론 정리 끝, 세션 캐시 예제 구현 중"}
{"at":"2026-08-27","sec":"1. What is Redis?","item":"Cache","lv":4,"ev":"세션 캐시 예제 구현"}
```

- 한 줄 = 판정 하나. `ev`(근거) 선택. 경로는 파일 위치가 담당
- **키는 `(sec, sub, 항목 이름)` 3종.** `sub` 없이 `(sec, item)`만 쓰면 같은 섹션 안에서 항목명이 겹치는
  60건이 한 키로 뭉쳐 하나만 해도 전부 완료로 잡힌다 — `redis` §4의 `Usecases`가
  `### Strings`·`Lists`·`Sets`·`Hashes`·`Sorted Sets` 아래 하나씩 있는 식(2026-08-26 수정)
- **`item`은 이름만 쓴다 — 설명은 키에서 뺀다** (2026-08-26 개정). 항목 텍스트가
  `English Name / 한국어 설명`이라 설명을 다듬을 때마다 기존 기록이 통째로 허공을 가리켰다.
  이름 = 첫 ` / ` 앞부분. 계산은 `tools/build_stats.py`의 `item_name`,
  화면은 `front/js/merge.js`의 `itemName` — 같은 규칙이니 한쪽만 고치지 말 것
- **따라서 같은 섹션(+서브섹션) 안에서 항목 *이름*이 겹치면 안 된다.** 겹치면 두 항목이 한 키로
  뭉친다. 개정 시점 실측 23985항목 = 유니크 키 23985개, 충돌 0
  (충돌 2건이던 `gcp` §7 `Cloud Run`·`cypress` §7 `Anti-pattern`은 이름을 구분되게 고쳐 해소)
- append-only. lv 상승·하강 전부 새 줄
- **승자는 `at`이 가장 늦은 줄** (2026-08-29 개정). 같은 날이면 파일 순서로 가른다 —
  하루에 `lv:1`→`lv:3`→`lv:4`를 잇달아 쓰는 게 정상 흐름이라서다.
  옛 규칙은 파일 순서만 봐서, **옛 날짜를 백필로 파일 끝에 덧붙이면 최신 판정을 조용히 덮어썼다.**
  덕분에 백필은 순서를 신경 쓸 필요가 없다 — 사건 날짜로 그냥 쓰면 제자리를 찾아간다.
  구현은 `build_stats.py`의 `read_log`와 `front/js/merge.js`의 `parseLog` **두 곳** — 한쪽만 고치지 말 것
- **잊어버린 항목은 오늘 날짜로 낮은 `lv` 한 줄을 덧붙여 내린다** (2026-08-29). 과거 줄은 지우지 않는다 —
  그 시점엔 실제로 해낸 것이고, 다시 손에 붙으면 높은 `lv`를 한 줄 더 얹어 복구한다.
  "이름만 남았다"는 `lv:1`, "설명은 된다"는 `lv:2`. 실증%는 내려가고 이력은 왕복까지 전부 남는다
- **실패한 시도도 한 줄** (2026-08-26 명문화) — `lv` 유지 + `doing:true` 유지 + `ev`에 전말
  (예: `{"at":"...","sec":"...","item":"...","lv":2,"doing":true,"ev":"협상 시도, 상대 조건 못 끌어냄"}`).
  같은 항목에 줄이 몇 개든 허용 — 집계는 `build_stats.py`가 키별로 `at`이 가장 늦은 줄만 취하므로 안 꼬임.
  성공만 기록하면 자기평가 조작과 같음. 결과 전용 파일은 이중 기록이라 금지
- 상세 전말(관찰·복기 기록물)은 `works/<로드맵 경로>/`의 md, 로그 `ev`에 경로 참조 — 로그가 목차, 파일이 본문

### `lv` + `doing` — 수준과 상태는 별개 필드 (2026-08-29 전환)

- **`lv`: 도달 수준 4단계.** 안함은 기록 없음
  | lv | 이름 | 판정 (3초 규칙) |
  |---|---|---|
  | 1 | 이름만 앎 | 들어봤는데 설명은 못 함 |
  | 2 | 개념을 앎 | 남에게 **한 문장**으로 설명 가능 |
  | 3 | 이론을 앎 | 어떻게/왜 동작하는지, 언제 쓰는지까지 설명 가능 (이해·대화 실증) |
  | 4 | 구현 가능 | 실전 실증 — 경로 3종(현장형/산출물형/채팅형)은 `docs/stat-model.md` 규칙 7 |
- **`doing`: 진행중 플래그. 수준과 직교** — 어느 lv에서든 붙는다.
  `lv:3, doing:true` = "이론 끝, 구현 진행중". 손 떼면 `doing` 없는 줄을 append
- **퍼센트는 숙련도 하나** — Σ`WEIGHTS[lv]`/분모, lv:1·2도 가중치만큼 든다
  (`WEIGHTS = {1:0.05, 2:0.2, 3:0.6, 4:1.0}`, 원본은 `tools/build_stats.py`).
  카드 색칠 폭도 같은 가중치다. 옛 실증%·학습% 두 개는 2026-09-01 폐기 —
  칸의 수준은 카드 lv 색이 이미 보여준다(`docs/stat-model.md` 규칙 7)
- 전환 사유: 구 단일 `s`(1 완료/2 이론/3 진행중)는 ① "이론완료 후 구현 진행중"을 표현 못 해
  구현을 시작하면 s:2가 s:3으로 덮여 **학습%가 내려갔고** ② "이름만 앎"과 "안 함"이 구분 안 됐다.
  구→신 대응: s:1→lv:4 · s:2→lv:3 · s:3→lv:1+doing (2026-08-29 전 로그 258줄 무손실 이관)

### `pick` — 택 1 주력 표식 (2026-08-30, 집계 무관)

```json
{"at":"2026-08-30","sec":"2. Pick a Language","item":"JavaScript (Node.js)","pick":true}
```

- 택 1 그룹에서 "내 주력"이 뭔지 표시하는 레코드. **수치·분모·그룹 상태에 안 들어간다** —
  고르기만 한 걸 완료로 세면 클릭 한 번이 진도가 되므로, 그룹 done은 여전히 실증 완료가 기준
- 같은 그룹에서 `pick:true` 중 `at`이 가장 늦은 하나만 유효(다른 옵션을 고르면 자연 교체).
  해제는 `{"pick":false}` append
- `build_stats.py`의 read_log는 pick 줄을 건너뛴다(lv·doing 필터) — 화면(`front/js/merge.js`)만 읽는다.
  그래서 pick 줄은 키 오타 검증을 안 받는다 — 프론트 에디터로 쓰면 키가 화면에서 오므로 안전
- **위임 칸에도 쓸 수 있다** — "위임 칸 로그 금지"의 유일한 예외(진행도가 아니라 선택 표식)

## Claude 갱신 규약

| 사건 | 기록 |
|---|---|
| 시작함 / 하다 맒 | log 현재 `lv` + `doing:true` + progress `doing` 추가 |
| 시도했으나 실패함 | log `lv` 유지 + `doing:true` + `ev`에 전말 |
| 이해함 (대화로 실증) | log `lv:3` (구현 연습을 이어가면 `doing:true` 병기) |
| 해냄 (실전 실증) | log `lv:4` — `doing` 뗌 |

- 로그 먼저, progress 반영. 같은 턴에 둘 다
- 이론 항목: 자기신고만으로 `lv:4` 금지 — 대화에서 실증했거나 작업물(`works/`) 있을 때만.
  실습 항목: 유형별 실증 — 현장형은 후기 자기신고 허용 (`docs/stat-model.md` 규칙 7)

### 입력 경로 2개 — 대화와 프론트 (2026-08-29)

- **대화**: Claude가 jsonl에 쓴다 (기존 방식, 판정 규칙의 본선)
- **프론트**: 항목 카드 클릭 → lv 버튼·진행중 체크·ev 입력 → `tools/serve.py`의 `POST /api/log`가
  같은 jsonl에 append하고 `build_stats.py`를 돌린다(progress·stats 재생성까지 한 번에).
  - **키 검증은 build_stats에 위임** — 로드맵에 없는 키면 exit 1을 받아 append를 되돌리고 400.
    검증 로직을 서버에 복제하지 않는다(원본은 하나). 위임 칸도 이 경로로 자동 차단
  - **lv:4는 ev 필수**(서버가 400) — 근거 없는 자기신고의 최소 방어선. 프론트 입력도 자기신고라
    판정 규칙 자체는 못 지킨다. 수상한 lv:4는 대화에서 오늘 날짜 하향 줄로 교정(잊음 규칙과 같은 장치)
  - 서버는 파일만 만진다 — git 커밋은 지금처럼 세션에서
- **로그를 쓰고 나면 `python tools/build_stats.py`** — progress·stats가 로그에서 다시 생성된다.
  progress를 손으로 고치지 않는다
- 재개 시 progress만 읽으면 된다 — ① `doing` 이어서 ② `secs`가 덜 찬 섹션 ③ 사용자가 고른 파트 아무 데나.
  **"다음 항목"이라는 개념은 없다.** 어느 파트를 먼저 하든 기록된다
- md 항목 텍스트 수정 시 log·progress 키도 같이 치환
